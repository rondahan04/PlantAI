PlantAI Stack

What's used, and which API gets called when.

APIs, tools & libraries

  • Expo / React Nativethe phone app itself
  • Node httpthe backend - no framework, one process
  • PlantNet APIidentifies the plant species from a photo
  • OpenAI (GPT-5.5, vision)diagnoses health from the photo; also extracts product info from scraped text
  • Google Places APIfinds nearby nurseries + their websites
  • Firecrawlscrapes a nursery's site to markdown
  • Tavilybackup scraper if Firecrawl fails
  • expo-sqlite / kv-storesaves the plant library on-device
  • expo-file-systemsaves plant photos on-device
  • expo-notificationsschedules watering reminders

Flow 1 - diagnose a plant

  1. App takes a photo, sends it to POST /api/diagnose.
  2. Server calls PlantNet → gets the species.
  3. Server calls OpenAI with the same photo + species → gets health, issues, care plan.
  4. App saves the result locally and schedules a watering reminder.

Flow 2 - find a nursery

  1. App sends location + plant name to POST /api/nurseries → gets a job id back right away (search can take minutes).
  2. Server calls Google Places → nearby nurseries with websites.
  3. For each one, server calls Firecrawl (or Tavily if that fails) to read the site, then OpenAI to pull out product + price.
  4. App polls GET /api/nurseries/job/:id until it's done, then shows the results on a map.

How the scraper adapts to each site

Every nursery's website is built on one of a handful of platforms, and each platform has its own search URL and its own markup. Rather than one scraper trying to parse every possible layout, the pipeline first figures out which platform a site is running, then uses the URL pattern that platform already supports.

  1. Fingerprint the homepage. The scraped markdown/HTML is checked for tells: cdn.shopify.com or /products/ means Shopify, wp-content or /product-category/ means WooCommerce, wixstatic.com means Wix.
  2. Reuse a known search pattern. Each platform maps to a search-URL template - Shopify is /search?q=, WooCommerce is /?s=&post_type=product, Wix is /search?q=. Recognizing the platform means the scraper already knows the right URL to hit, no guessing per site.
  3. Retry with the rendered page. Some storefronts build their markup client-side, so a static fetch shows nothing recognizable. If the first pass comes back unknown, the scraper re-fetches with JS rendering turned on.
  4. Ask OpenAI as a last resort. If the platform is still unrecognized, the page's scripts/CDN hints are handed to OpenAI to classify and to guess a search URL. That answer is saved to disk, so the same unfamiliar platform is never paid to classify twice.
